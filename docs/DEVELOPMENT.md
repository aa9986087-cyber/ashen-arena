# تطوير واختبار Ashen Arena

الهدف بوابة واحدة خفيفة، لا تغيير لمحرك اللعبة ولا إضافة إطار أثناء اللعب. ملفات `js/` تبقى سكربتات عامة مرتبة في `index.html`؛ أدوات الاختبار والتحليل تعمل في Node خارج اللعبة.

## كل ميزة قبل الإنتاج

ابدأ بفرع صغير، وافحص الدوال الموجودة قبل إضافة نسخة أخرى. المساعد العام يوضع في `js/core/` أو الوحدة المالكة، ويُحمّل قبل مستدعيه. أضف اختبارًا يصف السلوك الجديد أو يعيد إنتاج العطل، ثم أصلح بأصغر فرق. لا يكفي أن ينجح فحص صياغة الكود لإثبات صحة ميزة جديدة.

نفّذ `npm ci` ثم `npm test` للفحوص السريعة. اختبار الواجهة: `npm run test:fixtures` و`npx playwright install chromium` مرة أولى، ثم `npm run test:smoke`. اختبار smoke يستخدم Chromium الفعلي، main والتحديث والرسم الفعلي، ويمنع HTTP/WebSocket الخارجية باستثناء مكتبات موثقة مخزنة محليًا. لا ميكروفون ولا كتابة إلى قاعدة الإنتاج.

بعد نجاح الفحوص، `npm run package:game` يكوّن `dist/game` من `index.html` و`css/` و`js/` و`assets/` فقط. ملفات JavaScript وCSS في الحزمة تحمل معامل revision يعتمد على محتواها والنسخة؛ لا تعدّل عملية التعبئة المصدر. الاختبارات وSQL وnode_modules لا تُنشر.

## بوابة النشر — جاهزة، غير مفعلة بعد

ملف `.github/workflows/game-pages.yml` يشغّل فحوصًا على PR وعلى main، والنشر يعتمد على check وينشر artifact الصادر من نفس checkout. لا يُنشر PR. تُثبت مراجع Actions ومكتبات التطوير، وتُحفظ نتائج الإخفاق للمراجعة.

قبل تفعيل الإنتاج، يلزم بموافقة المالك: Pages → Source → GitHub Actions، وإلزام `check` في قواعد دمج main، ومنع تجاوزه حسب صلاحيات المالك. النشر القديم من main لا ينتظر هذه الفحوص؛ إضافة YAML وحدها لا تمنع تجاوزه. ملفات CI لم تُرفع وإعدادات GitHub لم تتغير.

التغييرات النصية لا تحتاج اختبارات شبكة إضافية، لكن القواعد الجديدة تحتاج اختبار قواعد، وواجهة جديدة تحتاج اختبار واجهة، وميزة شبكة أو SQL تحتاج أيضًا اختبارها الخاص في بيئة معزولة. المجموعة الحالية أساس وليست ضمانًا آليًا أن كل ميزة مستقبلية أصبحت مغطاة.

## خريطة الكود والتنظيف

`node tools/analyze-project.mjs docs/generated` يولد JSON للملفات والمتغيرات العامة والعلاقات وMermaid للوحدات. الاتجاه: الملف المستهلك → الملف الذي يعتمد عليه. مُحلّل النطاق يستبعد مراجع المتغيرات المحلية، ويستخرج موارد HTML ومعرّفات DOM والانتقالات الصريحة. لا يثبت تنفيذ كل مسار ديناميكي.

ملف `docs/generated/analysis.json` يحتوي مرشحات تكرار أو عدم استعمال؛ ليس قائمة حذف. `mkGift` مثلًا مقصود للاستدعاء من أدوات المطور حسب README، والنماذج والصوت محملة بأسماء مركبة، والواجهات البديلة والخلفيات الإجرائية ضرورية. لا تحذفها اعتمادًا على غياب مرجع مباشر.

أصلح التكرار المتكافئ فقط: مثال `copyToClipboard` يجمع آلية النسخ وتبقى رسائل النجاح/الفشل في كل ميزة. `clampToCircle` يوحد فقط إسقاطات الحدود المتطابقة؛ لا يوحد حدود ARENA وARENA+3 وARENA+4 المختلفة عمدًا. الصوت يحافظ على أسماء SFX وحدود التكرار المستقلة حتى عند توحيد التنفيذ.

## إصلاح SQL الإداري

تعريفات حذف المشرف المحلية تستخدم `IS DISTINCT FROM` لرفض NULL. `node tools/print-admin-guards.mjs` يخرج الدالتين من المصدر الأصلي دون اتصال بقاعدة البيانات. يجب اختبار سلوك المفاتيح NULL/الخاطئة/الصحيحة على قاعدة اختبار قبل طلب تطبيقه في الإنتاج؛ الاختبارات النصية الحالية تتحقق من الحارس ولا تنفذ PostgreSQL.

لا تعِد تشغيل ملفات المخطط القديمة كاملةً على قاعدة موجودة. إبقاء شروط الواجهات العامة ومراجعة rate limits والتزامن والملكية عمل منفصل موثق في تقرير المراجعة، ولا تُلغى واجهات قديمة قبل حصر مستدعيها.
